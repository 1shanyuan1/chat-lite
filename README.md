# Chat Lite

本地优先的 AI 聊天客户端。自己填 API Key，请求直连服务商，不经过任何中转；React + Capacitor 打包成 Android 应用。

## 功能

- 三种模式：极简（纯聊天 + 长记忆）、写作（长文 + 设定发展）、酒馆（角色卡 / 世界书 / 酒馆生态）
- 酒馆群聊子模式：自然 / 列表 / 轮流 / 手动四种发言顺序，交换 / 合并角色卡，静音、话痨度、强制发言、自动接话、群场景覆盖；每个角色独立成条消息
- 酒馆生态：卡内正则脚本、HTML 面板、快捷回复、变量与状态栏、深度注入、TavernHelper API 与事件、助手脚本
- 多服务商与模型、三种联网搜索、附件解析（PDF / Office / 压缩包）、辅助识图
- 多版本与分支树、压缩续接、会话搜索、完整导入导出
- 数据只存本机；应用内「关于 → 使用说明书」有面向新手的完整引导，「更新日志」按版本记录

## 开发

```bash
npm install
npm run dev        # 浏览器调试
npm run build      # 类型检查 + 打包
npm run selfcheck  # 离线自检（860+ 条断言，不联网）
npm run livecheck  # 真实接口联调，需 API_KEY=sk-xxx
npm run taverncheck # 酒馆模式全流程：导入角色卡 → 开场白 → 三轮对话，需 CARD=路径 API_KEY=sk-xxx
npm run tavernsweep # 多卡巡检：一次跑多张卡，横向比对解析与注入，需 API_KEY=sk-xxx
npm run cardcase -- 卡片路径 # 按真实导入路径解析一张卡，打印寄存区会显示成什么样（不联网、不写入）
npm run cap:sync   # 打包并同步到 Android 工程
npm run apk:debug  # 出 debug APK
```

## 隐私

API Key 只存在本机 `localStorage`，请求直连你填写的接口。应用不收集任何数据，没有账号体系。

## 已知限制

- **附件占空间**：图片以 base64、文档以抽出的原文存进 turns 表。Android 端走 SQLite 没问题；浏览器端 localStorage 只有约 5MB，带图或带长文档的对话存十几条就可能写不进去。
- **图片会重复计费**：多模态没有服务端会话状态，历史里的图片每一轮都会重新计费。应对是「图片保留轮数」（设置里可调，默认 2）——请求只给最近 N 轮（含本轮）带原图，更早的换成一行占位说明（模型知道有图但看不到）；识图描述本来就是文字，不受影响。DeepSeek 官方开源的 chat-demo 给了彻底解法：附件经 Files API 上传一次拿 `file_id`，历史轮次只发引用不发原图（本地缺原件的附件直接不进请求）——但并非每家服务商都有对应能力（DeepSeek 的 deepseek-flash 与 Anthropic / Gemini 有 Files API，OpenAI 聊天接口没有），见待办表。
- **文件类型**：能带图片，也能带**文档**——类型按内容魔数识别，不看扩展名。**PDF** 用 pdfjs 抽文本（worker 与 cmaps / 字体 / wasm 资源由 `scripts/pdfjs-assets.mjs` 拷进 `public/pdfjs/`，pdfjs 主模块和 worker 都是按需懒加载，不传 PDF 就不下载；扫描件没有文字层，抽不出来）；**Word / Excel / PPT**（.docx / .xlsx / .pptx）本质是 zip，不引大依赖直接解析包内 XML（表格按行列对齐、日期序列号转回日期）；**压缩包**把里面能转文本的文件都提出来，嵌着的 docx / xlsx / pptx / pdf / zip 也解析（下钻一层），二进制记数跳过；zip 是内存放大器，解压护栏（解压后单条 20MB / 全包总量 64MB）在中央目录阶段就把超限条目挡在门外——Android WebView 堆有限，OOM 会整页闪退；老格式 .doc / .xls / .ppt 是二进制 OLE，暂不支持，请另存为新格式。文本类（txt / md / json / csv / 代码等）照旧。
- **单条上限**：最多 9 张图片；文本附件超过 20 万字符会被截断（约 10 万汉字）。
- **思考强度**：档位由服务商的「方言」决定（见 [docs/reasoning-effort.md](docs/reasoning-effort.md)），模型元数据只用来收窄可选列表。不支持的档位不会出现在菜单里，也不会被悄悄替换。
- **长记忆（测试功能）**：设置里的「记忆」一节开启，只在极简模式生效。开启后模型能读写本机记忆文件（用户画像 / 会话索引 / 用户反馈），聊天页只显示成品回答，思考与工具调用都不渲染。**预算内交给 AI 经营**：画像默认预算 6000 token（设置里「记忆预算」自由填写——6000 是推荐值，上限放到 20 万，给 1M 级上下文的模型留空间；约一两百条 ≈ 一年的真实使用量）。平时模型只能追加；预算用到 60% 时自动让它把整份画像重写一遍——去重、合并、**淘汰过期与被推翻的结论**、按重要性重组——这个调用不进对话记录也不阻塞回答，设置里也有「整理画像」手动入口。预算是 AI 经营记忆的边界，不是它表达的天花板；预算太大主要代价是每轮注入的 token 成本（压缩预警会兜住占用）。整理是「单次重写整份画像」，受模型单次输出上限约束：画像超过 3 万 token 就跳过整理（明确提示，不硬写截断），预算照常生效、超了从最旧丢。保险：输出为空就拒绝写入、原画像不动；写入前把上一版存进备份记录（不进 prompt，出问题能找回）。会话索引仍然没有自动生成。点赞/踩并写下原因后，会额外调一次模型把反馈提炼成画像条目（这次调用不计入对话历史）。
- **联网搜索有三种方式**，在输入框的开关里自由选一：**模型内**（上游自带，能用的服务商优先推荐）、**本地源**（后端可选 DeepSeek Search / 自定义接口 / 模型内辅助调用，要配置才生效）、**Bing 兜底**（免配置，抓公开页面，质量一般）。
- **搜索可以借别的模型**：本地源选「模型内（辅助）」时，可以单独填一个搜索模型的地址/Key/模型名——主对话用 A、搜索借 B 的能力，主对话上下文不被搜索结果污染。
- **来源不一定全被引用**：回答下方的来源列表来自搜索接口，模型可能只引用其中一部分。
- **辅助识图**：从「已添加的服务商」里挑一个服务商，再从它的模型列表里选模型——能看图的排在最前并标「图」。图片先转成文字描述再交给主模型，主模型不需要支持看图。有独立开关，关掉就把原图直接发过去。模型列表和主对话共用同一份（缺缓存会自动拉一次，不要求你先去刷新过模型）。
- **辅助模型复用服务商**：填过 Key 的服务商都会被记住，辅助搜索/识图直接从列表里挑，不用重复填地址和密钥。只换了服务商没选模型时会退回当前对话的模型——拿 A 的模型名去请求 B 一定失败。
- **外观**：设置最上面的「色组（含明暗）」一节——**色组就是外观**，浅色/深色并入色组不再有独立开关。预设 17 个：6 色相 × 浅/深（石墨 / 靛蓝 / 松柏 / 胭脂 / 琥珀 / 鲜艳）+ 5 个纯色强对比（曜黑 / 藏青 / 墨松 / 酒红 / 牛皮纸）；「自定义」可配**主色（页面底）/ 中间色（气泡、输入框）/ 墨色（按钮等小部件）**三个表面色 + **字体颜色**（正文 / 次级 / 辅助）三路文字色，浅/深两套锚点各自独立存储。显式颜色原样生效；每个颜色只管自己的一层（分域直管），改一个颜色其它层不变。色阶全部写进 `--color-*` 变量全局生效（`src/ui/palette.ts`，不用 color-mix 以兼容老 WebView；旧 {h,s} / 扁平格式读取时兼容）。**消息样式**：平铺 / 气泡可切换，气泡模式下助手回复也装进气泡。**直角模式无例外**：连胶囊、圆形按钮一起归零。用户气泡单独一套颜色（`--bubble-*`，由中间色推演）。深色不是给每个组件加 `dark:` 变体，而是覆盖 Tailwind v4 的 `--color-*` CSS 变量反转中性色阶——所以 `bg-neutral-900 + text-white` 的主按钮会自动变成浅底深字。
- **过程区**：每条回答上方有一行折叠的「过程」，里面装思考原文和这轮的工具调用（搜索、记忆、回忆、设定），每条工具能点开看参数和结果。正文只放模型最后一轮的输出，中间轮的前导语（「我先查一下」）一律丢弃。所以「只输出正文」的提示词是真的成立，而且不用因为某个模式开了什么功能就把整块过程藏起来——长记忆模式下也能展开看。
- **提示词优先级**：模式规范排在最前（先定义这是什么场景），记忆与设定发展只补充「你有哪些能力」，不改变用户提出的任何要求，你自己挂的提示词排在最后——它的话优先于软件写的任何表达偏好。什么都没注入时补一句极简兜底，不会出现空 system。拼接逻辑集中在 `src/chat/prompt/`，全应用只有一处入口。
- **分支图（真正的树）**：聊天页右上角，设置图标左边。每个版本是一个节点，连线来自生成这一版时记录的前序版本；点卡片选择，可切到这一版、跳到这一轮，或导出这一版之上的单回复链。老记录没有来源，只能按当前选择推断，画成虚线。**只读**，不能增删。
- **导出单条回复链**：聊天里每条回答下面有「导出」，分支图里选中任意版本也有「导出这条线」。只导出这条链上的用户 / 助手内容（可选思考过程），不带用量、模型名和系统提示词；文件头会写明是「真实历史链」还是「按当前选择拼接」。说话人标签按模式取：酒馆用角色名，写作叫「叙述」，极简叫「助手」。
- **备选开场**：卡里的 `alternate_greetings` 会一起导入。还没开口时，开场消息下方有「换开场 N/M」，点开可以选任意一段；说过话之后入口消失——换了开场，后面几轮的对不上。
- **后置指令**：`post_history_instructions` 会作为一条 system 消息贴在对话历史末尾（比顶层 system 更靠近当前发言，权重更高）。Anthropic / Gemini 没有「消息里的 system」，会折进顶层 system 字段。
- **世界书**：按关键词匹配最近 6 条消息，支持 V2 的完整语义——`secondary_keys`（主键和二级键都要命中）、`selective`、`case_sensitive`、`match_whole_words`（仅对 ASCII 有效，中文自动退化成包含判断）、`insertion_order`。常驻条目必进且不受条数上限影响；命中多个关键词的排前面；同内容去重；总预算 900 token，超了跳过长条目。回答下方的「设定 N」标签可以展开看这一轮到底注入了哪几条。
- **我的名字 / 我的设定**：设置里的「角色扮演」一节。名字会替换角色卡里的 `{{user}}`；设定是一段自我介绍，挂在角色卡时注入 system，让角色知道你是谁。
- **舞台指令**：酒馆/写作模式下，最后一条回复下方有「继续 / 重写 / 更短 / 更细」。它们以 system 消息贴在历史末尾，角色听不见，也不进对话记录——所以不会出现「角色回应你的元指令」这种出戏。
- **设定发展模式（测试功能）**：设置里开启，只对写作模式生效。开新会话时把挂载的设定复制成一份「发展稿」，AI 写正文时如果引入了新地点、人物、规则，会自己调用 `update_setting` 补进去；原卡不动。模型只能追加、替换、删除条目，不能整份重写；你锁住的条目它碰不到。每次改动记一条变更历史（第几轮、改了什么、为什么），在寄存区的卡片详情里能看。同一张卡重复开会话会复用同一份发展稿。每 6 轮还会强制审查一次，防止模型偷懒。因为发展稿单向生长，发展模式下**不能切回旧版本、编辑旧轮次或原地分叉**（重新生成只允许最后一轮）；但导出单链和「从此链开新对话」不受影响——新会话沿用当前的发展稿，不回滚。
- **设定的整篇文本**：寄存区里打开写作设定，默认落在「整篇文本」——一份设定就是一段纯文本，正文在上，条目写成 `【条目：关键词, 关键词｜常驻｜锁定｜二级：…】` 开头的一段，没有标记就整篇都是正文。详情页可以导出 `.txt`、复制全文；写作区导入 `.txt` / `.md` 或点「新建」也按同一格式解析。**运行时语义不变**：正文仍然每轮注入，条目仍然按关键词命中，文本只是编辑与交换的形态。逐条改开关的「结构编辑」还在，两种视图随时切换。世界书与角色卡仍走原表单和卡片格式。
- **写作区「新建」**：顶层和文件夹里都先选「设定」还是「提示词」。设定可以直接开一份空白、把一大篇现成文字粘进来、从 `.txt` / `.md` 读取，或者交给 AI 整理成正文 + 条目；提示词是可复用的片段。三条设定路径都先打开文本编辑器，点「保存」才落库；AI 整理的结果会多一条「还没保存」的提示。新建面板会写明保存到哪个文件夹（顶层就是「不放进文件夹」）。
- **导入时可以 AI 整理**：新建时勾「让 AI 整理成条目」，模型会把它拆成常驻正文 + 关键词条目；结果先打开在文本编辑器里预览，点「保存」才写入。用当前对话的模型，单次最多 6 万字，这次调用不计入对话记录。整理只搬运、不改写，拿不准的内容留在正文。面板里还能写一段「前置说明」——它作为 system 的**最前面**一段，先交代这份设定是什么、给谁用、语气和边界，再执行整理规则；`【设定：】/【条目：】` 的标记格式仍然不能改，否则程序读不出来。这段说明会记住，下次沿用。
- **卡片可编辑**：寄存区里点角色卡可以改正文、开场白、备选开场、后置指令和关键词条目；条目能勾「常驻」、填二级关键词。
- **寄存区能一眼认出是哪张卡**：列表每条显示一行简介（角色卡取正文第一段，世界书取前几条关键词）、标签、条目数与开场段数；点进详情，顶部还有规范标识（V2 / V3）、作者、版本、常驻条目数和可展开的作者备注。作者/标签是从卡片元数据里读的，**旧版本导入的卡没存这些字段，删掉重新导入一次才会带上**（简介不受影响，它是由正文现算的）。
- **压缩续接**：上下文占用到预警线时，输入框上方会变成提醒条；点「压缩并开新对话」把更早的对话压成一段前情摘要，保留最近两轮原文。新会话继承角色卡、世界书、提示词和标题；摘要放在 system 里，聊天页顶部有可展开的「前情摘要」条，方便检查有没有漏。原会话不动，随时能回去。**预警线可以自己调**（设置里的「压缩预警」，50–95%，默认 80%）；平时不等提醒也能压——上下文那一行右侧一直有个「压缩」按钮。
- **群聊**：酒馆模式下的独立子模式（单聊 / 群聊）。勾两张以上角色卡开群，每个成员各出一条开场；发言顺序对齐 SillyTavern——自然（点名 + 话痨度）、列表（全员依次）、轮流（随机未发言）、手动（点谁谁说）。一次发送可让多个被激活的角色各自生成独立消息；群设置里能改交换 / 合并角色卡、静音、话痨度、成员排序、强制发言、自动接话与群聊场景覆盖。@点名参与自然顺序激活，群聊历史会给每条回复标上角色名。勾选只进「待挂」列表，第一句话发出去时才建会话并落库。
- **角色卡的头像不会导入**：JSON 卡里的 `avatar` 通常是外链（charhub 之类），导入时直接丢弃——本地优先的客户端不该为了头像去访问第三方。PNG 卡自带图，能正常显示。
- **PNG 角色卡按内容识别**：不看扩展名，`tEXt` / `zTXt` / `iTXt` 三种文本块都认；同时有 `chara`（V2）和 `ccv3`（V3）时优先 V3，空的 `ccv3` 占位块不会挡住后面的 `chara`。改错扩展名的卡（PNG 存成 `.json`、组合包存成 `.png`）也能直接导入。
- **无多语言**：界面只有中文。

## 备忘：聊天页真机可左右滑动（已修复）

**现象**：真机（Android WebView）上聊天消息区能左右拖动；桌面浏览器不明显。

**诊断**（2026-11-20，412×915 视口 + demo 数据）：修复前基线不溢出，但给用户气泡注入一段 170 字符无空格串后 `main.scrollWidth` 从 412 涨到 1793（溢出 1381px），markdown 段落里一条长 URL 溢出 775px，`main.scrollLeft` 可设到 300——横向拖动真实生效。原因两层叠加：

1. **容器**：消息区 `<main>` 只声明了 `overflow-y-auto`。CSS 规定一轴是 auto/scroll 时另一轴的 `visible` 会被计算成 `auto`——main 实际是双向滚动容器。
2. **内容**：正文没有断行兜底。用户气泡是 `whitespace-pre-wrap`，`.md` 段落也没有 `overflow-wrap`——长链接、模型名、base64、贴错日志这类无空格长串会把气泡和段落撑出可视宽度，溢出并入 main 的可滚动区域。

**修复**（三处）：

1. `src/App.tsx`：`<main>` 加 `overflow-x-hidden`——消息区只允许纵向滚；
2. `src/styles.css`：`main { overflow-wrap: anywhere }`——超长词在词内断行（只在放不下时生效，正常文本不受影响），全后代继承，气泡、用量行、来源标签一并覆盖；
3. `src/App.tsx` 的 `Markdown`：给 `table` 包一层 `overflow-x-auto`——超宽表格（长英文表头/单元格）在表内横滚，不撑破消息区；`border-collapse` 保持不变。

**验证**：`npm run build` 通过、`npm run selfcheck` 680 项全过；412×915 视口实测，修复前溢出 1381px 的长 token 气泡与 775px 的长链接均为 0 溢出（气泡内正常换行）；demo 里的真实 markdown 表格确认带上了横滚 wrapper；14 列超宽表格在 wrapper 内横滚（`scrollLeft` 可用）；**分支图画布容器（`overflow-auto`，位于 main 之外）双轴滚动不受影响**。真机生效需重新打包：`npm run cap:sync && npm run apk:debug`。
