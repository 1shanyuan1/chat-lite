## 二、统一规范（建议稿）

1. **人称**：一律「你」，不用「您」。（现状已一致，保持；memory.ts 提示词里对模型的「用户」不算文案）
2. **句末标点**：
   - 按钮/标签/状态行/占位符/单句错误与提示：句末不加句号
   - 成段说明与 confirm/alert 弹窗（多句）：按正常句法加句号
   - 工具结果短句（如「已记住 N 条。」）：统一去掉句末句号。现状两派，带句号的列入待定③：memory.ts:121「已记住 ${added} 条。」、「这些内容和已有的重复，没有新增。」、memory.ts:143「这些内容就在当前对话的上文里，直接看即可，不需要检索。」、memory.ts:144「没有找到包含「${query}」的历史对话。」、evolution.ts:171「没有需要记录的改动。」
   - 违反本条的单句界面提示：App.tsx:1029「点一下立即生效，不用保存。」、App.tsx:225「没拿到这个服务商的模型列表，重试，或在下面手填。」（建议去句号）
3. **符号**：问句用全角「？」；不用感叹号；省略号…；引号「」；括号（）；破折号——（现状已一致，成文即可）
4. **中英混排**：英文与中文之间留空格；单位小写 token/MB；专有名词规范大小写（API Key、Base URL、JSON、PNG、CHARX、SillyTavern、OpenAI/Anthropic/Gemini）。（现状已规范，保持）
5. **错误提示结构**：先说发生了什么，再给补救动作（「检查…」「改用…」）；不用「错误：」式前缀堆砌。现状 errors.ts 与各抛错文案基本符合；App.tsx:1243「拉取失败：{error}，可直接手填模型名」先因后果再补救，符合。
6. **语气**：平实直述；请求用户做动作可用「请」；不用训导式「请…再来」；不喊口号。现状 setting-format.ts:114「先在设置里填好 API Key，再来整理」是唯一接近训导式的句子，建议改「先在设置里填好 API Key，再开始整理」或并入待定项统一。
