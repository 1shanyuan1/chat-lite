# UI 设计评审：为什么「不够有序好看」

> 范围：当前版本全部界面（聊天页、起始页、会话抽屉、寄存区、设置面板、各弹层）。
> 方法：通读 UI 层源码（`src/App.tsx`、`src/ui/*`、`src/styles.css`）+ 412×915 视口浏览器实测。
> 本文只诊断不改动；每一节末尾给出「该做什么」，供下一轮设计迭代参考。

## 结论先行

产品的问题不是「丑在某一个屏」，而是**缺少一套被强制执行的视觉语法**。功能节奏迭代很快，每个面板都在按自己的手感取字号、圆角和间距，单看每一处都合理，合起来就是「密、碎、灰」。按平面设计四原则（对比 Contrast、重复 Repetition、对齐 Alignment、亲密性 Proximity）逐一检查， biggest 的三个元凶是：

1. **排印尺度崩塌** —— 70% 的界面文字 ≤11px，字号从 9 到 16 有 8 档、无阶差规律；
2. **对比度失效** —— 128 处 `text-neutral-400`（≈2.5:1）当正文用，15 处 `text-neutral-300`（≈1.5:1）几乎不可读；
3. **重复性缺失** —— 圆角 9 种取值、同类列表行三套规格、同样的「次级动作」有三种长相。

以下逐条展开，全部证据可复现。

---

## 一、排印（Typography）：字号即层级，尺度即气质

### 现状量化

对 `src/App.tsx` + `src/ui/*.tsx` 全量统计：

| 字号 | 出现次数 | 典型用途 |
|---|---|---|
| 9px | 7 | 「用这段」角标、寄存区标签 |
| 10px | **129** | 提示语、元信息、分组标题、说明文字 |
| 11px | **96** | 列表行、chips、按钮、次要操作 |
| 12px（含 text-xs） | 59 | 操作行、抽屉搜索框 |
| 13px | 5 | 模式卡标题、思考原文 |
| 14px（text-sm） | 28 | 输入框、列表主标题 |
| 15px | 2 | 顶栏标题 |
| 16px | 3 | **聊天正文**（唯一的阅读层） |

**约 70% 的界面文字 ≤11px，约 80% ≤12px。**

### 用设计理论解释为什么它「不好看」

- 平面设计里，字号阶（type scale）是页面的**骨架**。成熟产品通常只有 4–6 档且彼此有固定倍率（如 12 / 14 / 17 / 22 / 28）。8 档无规律字号意味着「层级靠拍脑袋」，两处 10px 可能承载完全不同的重要性——层级信息在视觉上失效，用户只能靠读内容理解界面，而不是靠看。
- 10px 对 CJK 是低于可读下限的（中文 UI 常用下限 12px，Material 建议正文 ≥12sp）。大量 10px 导致整个 UI 的「字面密度」远超内容实际需要的密度——**密密麻麻的廉价感主要来自这里**，而不是配色或布局。
- 16px 正文与 10–11px 元信息之间有 5–6px 的断层，中间没有过渡层级。结果是每条回答下方贴着一坨「更小一码的世界」：舞台指令、复制/导出/重新生成、赞踩、用量行、模型名、字数、耗时、命中数……全部挤在 10–12px 区间互相争抢。

### 该做什么

定 5 档字阶（例：12 辅助 / 14 界面默认 / 16 正文 / 17 标题 / 22 大标题），把 9/10/11px 全部并入 12–13px；**元信息靠字重和灰度区分，不靠缩小字号**。

## 二、对比（Contrast）：层级靠「变浅」，于是浅到读不见

### 现状量化

| 用法 | 次数 | 白底对比度 | WCAG AA（4.5:1） |
|---|---|---|---|
| `text-neutral-400`（#a3a3a3） | **128** | ≈2.5:1 | **不及格** |
| `text-neutral-300`（#d4d4d4） | 15 | ≈1.5:1 | 几乎不可见 |
| `text-neutral-500`（#737373） | 66 | ≈4.7:1 | 勉强及格 |
| `text-neutral-600`（#525252） | 52 | ≈7:1 | 及格 |

`text-neutral-400` 是全产品使用量第一的文字色（超过任何一种主文字色）。抽屉里的「改名/删除」、每条回答下的操作行、设置里全部说明文字、用量行、过程区标题……全在 2.5:1 上挣扎。更极端的是寄存区和起始页的「删」按钮用了 `text-neutral-300`（1.5:1）——**危险操作是全界面最看不见的东西**。

### 理论解释

设计的层级本来应该由「字号 × 字重 × 颜色 × 留白」四个变量共同承担。这套 UI 的字号被压平之后，层级几乎全压在「灰度」一个变量上，于是灰度被用过头：-400、-300 这种值本来是给**禁用态/占位符**的，被拿来当辅助正文。后果有两层：

1. **可读性**：浅色主题下大量文字不达 AA；深色主题反而更好（neutral-400 映射为 #7c7c86，对比 ≈4.6:1）——同一个产品两种主题的层级感不一致。
2. **强调失效**：当所有东西都「浅」，真正需要突出的东西（顶栏标题 15px 中字重）反而不突出。对比原则的本质是**重要的更重，而不是不重要的更轻**。

另外产品没有品牌强调色：主操作是「黑」，链接是 Tailwind 默认蓝（#2563eb），世界书标签是 emerald，警示是 amber——四种色相之间没有共同的明度/饱和度处理，emerald 和 amber 的出现显得像「借来的颜色」，破坏了原本干净的黑白灰系统。

### 该做什么

立灰度纪律：辅助文字 ≥ neutral-500，界面默认 ≥ neutral-600，正文 neutral-800；-300/-400 只允许用于禁用态和占位符；「删」类危险操作固定红描边样式。若要强调色，只加一个（与黑主色互补的低饱和色），emerald/amber 降格为「仅状态语义」。

## 三、重复（Repetition）：同一个系统里长出了好几套控件

### 现状量化

**圆角**：9 种取值并存——`rounded`(4px) ×19、`rounded-md` ×13、`rounded-lg` ×66、`rounded-xl` ×27、`rounded-[14px]`、`rounded-[18px]`、`rounded-[22px]`、`rounded-2xl`(弹层)、`rounded-full` ×33、以及 `rounded-sm` ×1。同类元素不同档：气泡 18px、输入框 22px、模型卡 lg(8px)、模式卡 xl(12px)、Sheet 头部 2xl(16px)。

**同类组件多套规格**：四个「带搜索的列表选择器」各自手写——

- `ProviderPicker` 行：`px-3 py-2 text-xs`，容器 `rounded-lg`
- `AuxModelPicker` 行：`px-2.5 py-1.5 text-[11px]`，容器 `rounded-lg`
- `ModelPicker` 行：`px-3 py-2 text-xs`，容器 `rounded-lg`（含价格第二行）
- 会话抽屉 `SessionRow`：`px-4 py-2.5 text-sm`

同一交互（点选一行）在四个地方有四种密度和三种字号。

**次级动作三种长相**：pill（`bg-neutral-100 rounded-full`，如舞台指令）、纯文字链接（`text-[12px] text-neutral-400`，如复制/导出）、描边按钮（`border-neutral-200`，如压缩、导入）。同一条回答的操作区里 pill 和文字链接混排在一行。

**配置生效语义不一**：外观两档点击立即生效（`saveConfig` 直调），搜索模式在输入框里点了也立即生效，而设置面板里改的其它十几项要点最底部的「保存」——面板里有 12+ 组控件，用户无法预测哪几个改动已经生效。

### 理论解释

Repetition 原则：重复的元素让页面的一切「看起来属于同一个系统」，是「有序感」的最大来源。上面每一处漂移单独看都是小事，但它们累积出的观感正是「这是很多个晚上各自赶出来的面板拼起来的」——这就是用户说「不够有序」的底层原因。

### 该做什么

- 圆角收敛到 3 档：8（小控件）/ 16（卡片、面板）/ full（圆形件），`data-corners=sharp` 已经能一键归零，说明收敛完全可行；
- 抽一个 `ListRow` / `PickerSheet` 组件，四个选择器共用；
- 次级动作统一为一种控件（建议 pill），危险动作统一红描边；
- 设置面板要么全部即时生效、要么分组小节各有「生效中」状态提示。

## 四、亲密性（Proximity）：该抱团的没抱团，该收起的没收起

### 现状描述

**消息区**：一条回答下方最多可堆 4 层附属物——①舞台指令 pill 行；②复制/导出/重新生成/变体切换行；③赞踩反馈块；④用量行（模型名、字数、耗时、入/出 token、命中率）。四层全部直接贴在正文下，视觉权重与正文几乎同区。中间轮次与最后一轮的附属物数量不同，滚动时界面「忽胖忽瘦」。

**输入区**：输入框上方同样可叠 5 层——上下文用量条、模型/思考/联网三颗 chips、三块可展开面板（搜索/模型参数/思考强度）、预设动作行、附件行。全部常驻垂直堆叠，最坏情况输入框被推到只剩一行。

**设置面板**：外观、服务商、搜索、识图、协议、模型、上下文、压缩、写作、角色扮演、记忆——11 组控件一长条滚动，仅靠 `mt-4 border-t` 分隔，无小节标题体系（部分有 border-t + 文字标题，部分没有），扫读成本高。

### 理论解释

Proximity 原则：相关的元素靠近成组，无关的用留白隔开。现在的问题是**组内的东西太多**（一条回答的附属物远超一条消息应有的视觉重量）而**组间没有真正的呼吸**（消息间距 mb-6 与附属物行距是同一数量级）。聊天产品里正文是唯一主角，附属物应当被压缩成一行可展开的「详情条」——代码里其实已有这个模式（过程区 Process、用量 statsOpen 的折叠），方向是对的，只是没有贯彻到所有附属层。

### 该做什么

每条回答固定一行元信息（可展开），舞台指令保留（它是写作功能的主角之一）但与变体切换合并；输入区把三块面板改成统一的单一面板容器（一次只开一块，目前互斥逻辑已有，但视觉上各是各的样子）；设置面板按「连接 / 生成 / 行为 / 外观」四节重排，每节有标题行。

## 五、对齐与间距（Alignment & Spacing）：网格存在，纪律不在

### 现状描述

布局骨架其实是好的：整体 `max-w-[720px]` 居中、flex 纵向三段（顶栏/消息/输入）、抽屉 `w-[82%] max-w-[340px]`，这些都是正确的决定。问题在微观间距的取值漂移：

- 水平内边距同层混用 `px-2 / px-2.5 / px-3 / px-4`：设置面板 `p-5`，Sheet `p-4`，抽屉 `px-4`，消息区 `px-4`，chips 行 `px-2`——同样是「面板内容距边」，四种答案；
- 垂直节奏 `py-0.5 / py-1 / py-1.5 / py-2 / py-2.5 / py-3` 在同一层级里随机出现；
- 开始页三张模式卡 `px-1.5 py-2.5`，卡内 10px 提示文字在 1/3 宽的卡里换行参差，三张卡的文字高度不一致（底部没对齐）。

### 理论解释

对齐原则下，任何元素都应能与另一条参考线对得上。4pt 网格本身已经有了（Tailwind 的 0.5 步长 = 2px），坏的是**同层取值不一致**——用户看不到代码，但能感觉到「每个面板的呼吸都不一样」，这就是「不精致」感觉的来源之一。起始页是第一印象屏，三卡文字底部参差会直接拉低整个产品的精致度。

### 该做什么

同层级内边距取同一档（面板统一 p-4、列表行统一 px-4 py-2.5 或 px-3 py-2，二选一全局贯彻）；模式卡提示文字限两行（`line-clamp-2`）保证卡高一致。

## 六、层次与视觉噪音（Hierarchy）：界面在跟内容抢戏

综合以上四条，聊天页（核心屏）的视觉预算分配是失衡的：

- **正文** 16px / 1.75 行高、单色黑——克制、正确；
- **附属层** 10–12px、五级灰度、多色相点缀（amber/emerald/red/blue）——喧闹；
- **一个回答的完整高度**里，正文可能只占 40–60%，其余是过程区、来源 chips、操作行、赞踩、用量。

平面设计里「好看」的第一公式：**主体占比越大越美**。聊天产品的主体是对话文字，当每屏有 6–8 种字号、5 种灰度、4 种控件形状同时在场上，即使每一件都做得对，整体也必然显乱。修齐的路径不是「重画」，而是收敛：字号收敛（一）、灰度收敛（二）、控件收敛（三）、附属物收敛（四）——四件事做完，产品会自然「有序好看」。

### 该做什么

给聊天页定一条硬规矩：**同一时刻视口内 ≤4 种字号、≤4 种灰度、≤2 种控件形状**。

## 值得保留的优点（不要在重构中丢掉）

1. **主题变量化架构**（styles.css：换肤只覆盖 `--color-*`，直角模式一个选择器归零圆角）——这是比多数成熟产品都干净的做法，收敛控件时继续走变量路线；
2. **平台细节**：安全区 `env(safe-area-inset-*)` 全覆盖、软键盘 `--app-height` 锁定、老 WebView 的 sRGB/rgba 兜底、触屏与鼠标滚动条分设备处理——工程审美在线；
3. **信息架构**：过程区折叠、用量折叠、前情摘要折叠，「展开看细节」的交互模式已经存在且一致；
4. **可达性意识**：图标按钮都有 `aria-label`，危险操作有 confirm。

## 修复优先级建议

| 级别 | 内容 | 理由 |
|---|---|---|
| P0 | 字阶收敛（消灭 9/10/11px）+ 灰度下限（消灭 -300/-400 作正文） | 影响每一屏，收益最大 |
| P1 | 圆角/间距/列表行收敛成组件 | 消除「拼装感」 |
| P1 | 每条回答的附属层合并为一行可展开详情 | 还正文以主角地位 |
| P2 | 设置面板四节重排 + 生效语义统一 | 扫读效率 |
| P2 | 模式卡文字对齐、强调色策略 | 第一印象与品牌感 |
